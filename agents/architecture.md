# Architecture

## Runtime pipeline

```
docker run → /entrypoint.sh
    │
    ├─ [if inventory.yaml.j2 exists]
    │       render_helpers.py loaded via sys.path.insert(0, '/')
    │       Jinja2 renders inventory.yaml.j2 → inventory.yaml
    │       (Proxmox REST API calls happen here)
    │
    └─ cd /workspace/sources/project
            pulumi preview
            pulumi up --yes
                └─ __main__.py runs
                        load_inventory("/workspace/inventory.yaml") → Inventory
                        builder functions create Pulumi resources
```

## Docker image

```dockerfile
# Dockerfile key points
FROM oraclelinux:10-slim
# Pulumi CLI extracted to /usr/local/bin/
# pip: pulumi pulumi-proxmoxve==8.0.0 pydantic pyyaml jinja2
ENV PYTHONPATH=/workspace/sources   # makes sources/ importable without package install
COPY entrypoint.sh /entrypoint.sh
COPY render_helpers.py /render_helpers.py  # available at render time via sys.path.insert(0, '/')
```

The user mounts the **root of this repository** at `/workspace`:

```bash
docker run -v "$(pwd):/workspace" pulumi-proxmoxve
```

Expected layout inside `/workspace` (= repo root):

```
/workspace/
├── inventory.yaml.j2       # user's config template (OR pre-rendered inventory.yaml)
├── inventory.yaml          # generated by entrypoint from .j2 (gitignored)
├── pulumi-state/           # Pulumi local backend state (gitignored)
└── sources/                # Python source tree (part of this repo)
    └── project/
        ├── Pulumi.yaml
        └── __main__.py
```

`sources/` is part of the repository — it is NOT something the user provides separately.

## Jinja2 render phase

`entrypoint.sh` runs an inline Python heredoc:

```python
sys.path.insert(0, '/')        # so 'import render_helpers' finds /render_helpers.py
from render_helpers import JINJA2_GLOBALS

jenv = jinja2.Environment(loader=jinja2.FileSystemLoader(tmpl_dir))
jenv.globals['load_yaml'] = load_yaml   # helper: load another YAML/j2 file
jenv.globals.update(JINJA2_GLOBALS)     # all Proxmox REST API helpers
rendered = jenv.get_template(tmpl_name).render(env=os.environ)
```

`env` is `os.environ` — all shell environment variables are available in templates as `{{ env.MY_VAR }}`.

`load_yaml(path)` can load another `.yaml` or `.yaml.j2` file relative to the template directory. If the file ends with `.j2`, it is rendered first.

## Pulumi execution phase

`sources/project/__main__.py` is the Pulumi program. It:

1. Calls `load_inventory("/workspace/inventory.yaml")` → validated `Inventory` object
2. Creates a single `proxmox.Provider` from `inv.provider`
3. Calls builder functions in dependency order (RBAC → firewall → ACME → cluster_misc → storages → network → node_config → downloads → pools → HA → backup → replication → SDN → SSH/cloud-init → VMs → LXC)
4. Exports `ssh_private_key`, `ssh_public_key`, `vm_ips`

## Pulumi state

State is stored locally at `/workspace/pulumi-state` (file backend, no Pulumi Cloud required). Stack name is `default`.

## Environment variables consumed at runtime

| Variable | Purpose |
|---|---|
| `PULUMI_BACKEND_URL` | Set to `file:///workspace/pulumi-state` in Dockerfile |
| `PULUMI_CONFIG_PASSPHRASE` | Set to `""` (no encryption) |
| `PULUMI_PYTHON_CMD` | Set to `python3` |
| Any custom var | Available in Jinja2 templates as `{{ env.VAR_NAME }}` |
